Industrial EDA + Dashboard

ทำอะไร

วิเคราะห์ข้อมูลเซ็นเซอร์เครื่องจักร 10,000 records จาก AI4I 2020 dataset เพื่อหา insight ทางธุรกิจ เช่น "เครื่องเสียกี่ %?", "สาเหตุไหนพบบ่อย?", "เครื่องเกรดไหนเสี่ยงสุด?" แล้วสร้าง Looker Studio dashboard ให้ผู้บริหารดูได้

ทำเสร็จแล้วได้อะไร
  • EDA notebook 37 cells พร้อม insights
  • Looker Studio dashboard public link
  • GitHub repo ที่สมัครงานเอาไปแสดงได้
  • ความเข้าใจข้อมูลที่ใช้ต่อใน Project #2

เครื่องมือที่ใช้

Python 3.10 pandas numpy matplotlib seaborn Jupyter Notebook SQL (optional) Google Looker Studio Git/GitHub

ขั้นตอนการทำ — 6 ขั้น

1
Setup โปรเจคและโหลดข้อมูล
สร้าง folder structure ใน VS Code · ดาวน์โหลด ai4i2020.csv จาก Kaggle ใส่ใน data/raw/ · ติดตั้ง dependencies ผ่าน requirements.txt · เปิด Jupyter notebook
2
ตรวจคุณภาพข้อมูล
รัน df.info(), df.isna(), df.duplicated(), df.describe() · ยืนยันว่ามี 10,000 rows · 0 missing · 0 duplicate · ค่าทุก column อยู่ในช่วงที่สมเหตุสมผล
3
Univariate Analysis (วิเคราะห์ทีละตัวแปร)
วาด histogram + KDE ของ sensor 5 ตัว · นับ failure rate รวม (3.39%) · แยกสาเหตุ HDF/OSF/PWF/TWF/RNF · นับเครื่องในแต่ละเกรด L/M/H
4
Bivariate Analysis (หาความสัมพันธ์)
วาด KDE เทียบ healthy vs failure · สร้าง correlation heatmap · พล็อต scatter Torque×RPM พบ "โซนอันตราย" (T>60, RPM<1400) · feature engineering: สร้าง temp_gap, n_failure_modes
5
บันทึก clean dataset และสร้าง dashboard
Export ai4i_clean.csv ที่เปลี่ยนชื่อ column เป็น snake_case แล้ว · upload เข้า Looker Studio · สร้าง 4 KPI scorecards + donut + bar + scatter · ทำ public link
6
เขียน README + push GitHub
README ต้องมี: Problem Statement · Key Findings (ตัวเลขจริง) · Tools Used · Setup Instructions · Business Impact · Dashboard link · push ขึ้น repo ชื่อ industrial-eda-dashboard

Key Insights ที่เป็น "หมัดเด็ด" ในการสัมภาษณ์

Insight #1 — โซนอันตราย

เจอกฎเดียวที่ใช้ได้: Torque > 60 Nm + RPM < 1,400 = failure rate 40.1% (12× สูงกว่า baseline) — เอาไปทำ alert ในโรงงานได้เลย ไม่ต้องใช้ ML

Insight #2 — HDF คือสาเหตุอันดับ 1

33.9% ของการเสียมาจาก Heat Dissipation Failure — แก้ปัญหา cooling system ลด downtime ได้ 1 ใน 3

Insight #3 — เกรด L เสี่ยงสุด

เกรด L (3.92%) เสียมากกว่าเกรด H (2.09%) เกือบ 2 เท่า — จัด maintenance budget ตามนี้

Insight #4 — Linear correlation อ่อน

ค่า correlation ทั้งหมด < 0.25 — ความสัมพันธ์เป็น non-linear → ML model จะมีประโยชน์ใน Project #2

Predictive Maintenance ML Model

ทำอะไร

ใช้ข้อมูล AI4I เดิมจาก Project #1 มาสร้าง ML classification model ที่ทำนายว่าเครื่องจะเสียก่อนเสียจริง (Random Forest หรือ XGBoost) · evaluate ด้วย Precision/Recall/F1 · คำนวณ ROI ที่ประหยัดได้

ทำเสร็จแล้วได้อะไร
  • Trained ML model (.pkl file)
  • Performance metrics report
  • ROI calculator (บาทประหยัดได้)
  • Updated dashboard ที่โชว์ predictions

เครื่องมือที่ใช้ (เพิ่มจาก Project #1)

scikit-learn XGBoost imblearn (SMOTE) joblib (save model) SHAP (feature importance) Looker Studio

ขั้นตอนการทำ — 7 ขั้น

1
Feature Engineering ขั้นสูง
นอกจาก temp_gap จาก #1 — สร้าง rolling averages, lag features, power = torque×rpm, tool_wear × torque interaction, threshold flags
2
Train/Test Split + Handle Imbalance
Stratified split 80/20 (เพราะ class imbalance หนัก 3.39% vs 96.61%) · ใช้ SMOTE หรือ class_weight='balanced' · จะเลือกใช้แบบไหนแล้ว trade-off ยังไง
3
Train Baseline Model
Logistic Regression baseline (เพื่อเทียบ) · Random Forest 100 trees · XGBoost · Cross-validation 5-fold · เก็บ metrics ทั้งหมด
4
Hyperparameter Tuning
ใช้ GridSearchCV หรือ RandomizedSearchCV · ปรับ n_estimators, max_depth, min_samples_split · ใช้ F1-macro เป็น scoring
5
Evaluate + Explain
Confusion matrix · Precision/Recall/F1 ต่อ class · ROC-AUC · SHAP values เพื่ออธิบายว่า feature ไหนทำนายอะไร · เปรียบเทียบกับ baseline (กฎ Torque>60 ของ Project #1)
6
ROI Calculation
ถ้า model จับ failure ได้ X% ก่อนเกิด → ลด downtime Y ชั่วโมง/เดือน → ประหยัดเงิน Z บาท · นำเสนอเป็นกราฟ ROI ใน dashboard
7
Update Dashboard + Document
เพิ่มหน้าใหม่ใน Looker dashboard ที่โชว์ predictions · confidence scores · maintenance alerts · update README · อธิบาย trade-off ใน model ให้คนไม่ใช่ data person อ่านรู้เรื่อง
⚠️ Trade-off ที่ต้องตัดสินใจ: ใน predictive maintenance — Recall สำคัญกว่า Precision · พลาด failure 1 ตัว = downtime ราคาแพง · false alarm 1 ครั้ง = แค่ตรวจเสียเปล่า — เน้นจุดนี้ใน interview

คำถามที่ Interview จะถามเรื่อง Project นี้

Q: ทำไมเลือก XGBoost ไม่เลือก Logistic Regression?

A: Linear correlation ทั้งหมด < 0.25 (จาก Project #1) → ความสัมพันธ์เป็น non-linear · tree-based models จับ interaction (เช่น torque×rpm) ได้ดีกว่า · XGBoost ทน outliers ใน sensor data

Q: จัดการ class imbalance 3% ยังไง?

A: ลอง 3 วิธี: SMOTE, class_weight='balanced', threshold tuning · เลือกที่ Recall สูงสุด (เพราะพลาด failure แพงกว่า false alarm) · validate ด้วย F1-macro

Q: Model พลาดเครื่องเสีย 1 ตัว ใครเสียหาย?

A: ใช้ confusion matrix อธิบาย: 1 false negative = ~30 นาที downtime × 50,000 บาท/ชม. = 25,000 บาท · เลย optimize Recall ดีกว่า Accuracy

Q: ทำไม ML ดีกว่ากฎ "Torque>60+RPM<1400"?

A: กฎ rule-based จับเฉพาะ OSF/PWF · ML จับ HDF, TWF ที่ไม่อยู่ในกฎด้วย · ROC-AUC ของ ML > 0.85 vs rule ~ 0.65 — ROI สูงกว่า

Computer Vision QC System

ทำอะไร

สร้าง CNN model ที่ตรวจจับ defects บนพื้นผิวโลหะจากภาพ (ใช้ NEU Dataset) ครอบคลุม 6 ประเภท defect: pitting, scratches, crazing, etc. · ทำ demo video เครื่อง detect แบบ real-time

ทำเสร็จแล้วได้อะไร
  • Trained CNN model
  • Real-time defect detection demo
  • Demo video (60-90 วินาที)
  • QC metrics dashboard

เครื่องมือที่ใช้

OpenCV TensorFlow / Keras PyTorch (alternative) torchvision Pillow streamlit / gradio OBS Studio (record)

ขั้นตอนการทำ — 8 ขั้น

1
Setup CV environment
ติดตั้ง tensorflow, opencv-python, pillow · ตั้งค่า GPU (ถ้ามี) · ดาวน์โหลด NEU dataset (~100 MB) · explore ภาพแต่ละ class
2
Data Augmentation + Preprocessing
ใช้ ImageDataGenerator หรือ tf.keras.preprocessing · rotation, flip, zoom, brightness · resize ทุกภาพเป็น 224×224 (สำหรับ pretrained model)
3
Transfer Learning จาก pretrained model
โหลด ResNet50, VGG16, หรือ EfficientNetB0 ที่ pretrained บน ImageNet · freeze base layers · เพิ่ม dense layer ใหม่ 6 classes
4
Train + Fine-tune
Train head อย่างเดียวก่อน 10 epochs · จากนั้น unfreeze ทั้งหมด train ต่อด้วย learning rate ต่ำ · ใช้ EarlyStopping + ReduceLROnPlateau
5
Evaluate
Test set accuracy · per-class precision/recall/F1 · confusion matrix 6×6 · บันทึก top-5 misclassifications · เป้าหมาย: accuracy > 90%
6
Build Real-time Demo
ใช้ streamlit หรือ gradio สร้าง web app ที่ upload ภาพ → predict → แสดงผล · เพิ่ม heatmap (Grad-CAM) ที่โชว์ว่ามองตรงไหน
7
บันทึก Demo Video 60-90 วินาที
ใช้ OBS Studio บันทึกหน้าจอ · upload ภาพ defect 5-6 ภาพต่างชนิด · โชว์ prediction + heatmap · ใส่ caption ภาษาอังกฤษ · upload YouTube หรือ embed GitHub
8
Document + Push GitHub
README ต้องมี: link วิดีโอ demo (สำคัญมาก!) · accuracy table · sample predictions · architecture diagram · instructions to run · push to industrial-cv-qc
🚨 เคล็ดลับหลัก: ใน Project นี้ วิดีโอ demo สำคัญที่สุด — เพราะ HR ส่วนใหญ่ดูไม่ออกว่า model accuracy 95% หมายถึงอะไร แต่เห็นเครื่องตรวจจับ defect แบบ real-time = ประทับใจทันที
